# sad

> Documentation gate for code: comments and doc strings are treated as
> evidence the code failed to express itself, so prose outside four
> structural channels becomes a finding.

sad is a Rust CLI that runs `sad check` over a source tree and emits a
genesis suite envelope of findings. It parses Rust, Python (including
`.pyi` stubs), TypeScript, and JavaScript with pinned tree-sitter grammars
over the gated extensions `.rs`, `.py`, `.pyi`, `.ts`, `.js`, and `.mjs`,
and attributes every comment or doc-string node structurally — node kind,
position, leading token — never semantically. Exit status mirrors the
envelope's `ok`: 0 on pass, 1 when error-severity findings block.

## Key commands

- `sad check` — gate the default attribution scope (files whose governing
  revision carries the configured attribution trailer, plus new/untracked
  files); non-zero exit when error-severity findings block
- `sad check --all` — analyze every non-excluded file (required for CI and
  for adopting the gate on an existing tree)
- `sad check --adopt` — write `sad-baseline.json` of grandfathered finding
  IDs, commit it, evaluate against it; the baseline is shrink-only, so
  growing it fails the run
- `sad version [--json]` — tool identity as a genesis suite envelope
- `sad doctor [--json] [--fix]` — structured diagnostics for the cwd:
  `sad.toml` validity, the `sad-check` managed block in `.lefthook.yml`
  (warns with a `sad hooks install` remediation; `--fix` wires it), and
  `sad-baseline.json` integrity; ok:false only on failed checks
- `sad feedback [--json] <kind> [--title <t>] [--dry-run] [--from-last-error]`
  — file an issue (bug|feature|question|chore) against `charly-vibes/sad`
  via `gh`; reporting-only, never affects check results
- `sad completions <shell>` — print shell completions (bash, zsh, fish,
  powershell, elvish); raw stdout, not an envelope

Flags accepted by `check`: `--json` (raw envelope), `--all`, `--adopt`,
`--strict`, `--config <path>`.

## Checks

| Check | Finding |
|---|---|
| `comment_outside_channel` | prose attributed to no channel |
| `commented_out_code` | prose block whose normalised body is code-shaped |
| `doc_summary_cap_exceeded` | doc summary lead over the configured cap |
| `unresolvable_marker` | marker-prefixed ID that resolves to nothing |
| `missing_header` | first block lacks a required header keyword, when enabled |
| `suppression_cap_exceeded` | file over its suppression cap |

Errors block: narration, apology, todo, `commented_out_code`, and the
structural findings. Warnings report: banner, unclassified, and the doc
cap. Finding IDs are stable — `<path>::<symbol-path>::<content-hash>` — so
they survive line drift and unrelated edits. File-scoped findings use `-`
as the symbol-path component.

## Channels and exemptions

Legitimate prose lives in exactly four places: the file header (must
contain `Purpose`, `Responsibilities`, and `Rationale` when
`require_header` is on), the doc channel (summary lead capped, structured
sections after the first blank line uncapped), traceability markers
(`marker_prefix` + `marker_pattern`, resolvable against
`.beads/issues.jsonl` or `openspec/specs/`), and rationale (a leading
`SAFETY:`, `INVARIANT:`, `SECURITY:`, or `WHY:` tag with a non-empty
body). Licence/SPDX headers produce no findings, and nor do licence
lines beside the tag that open with `Copyright` plus a year, `(c)`, or
`©`, a leading `©` or `(c)`, `Licensed under`, `License:`, or
`All rights reserved`. `@generated` regions, `exclude` globs, and Python
file metadata (a shebang on source line 1, a PEP 263 coding cookie on
lines 1–2) are likewise exempt. Suppressions (`# noqa`,
`# type: ignore`, `// @ts-ignore`, `// @ts-expect-error`,
`// eslint-disable-*`, `sad:ignore <check-id> <reason>`) are exempt but
counted as `suppression_debt` in the envelope.

## Configuration

`sad.toml` at the repository root, discovered after `--config <path>`.
Knobs: `checks`, `doc_summary_cap`, `marker_prefix`, `marker_pattern`,
`resolvers`, `require_header`, `suppression_cap`, `exclude`,
`attribution.trailer`.

## Source layout

```
sad/src/
  main.rs          CLI entry-point
  cli.rs           clap command surface
  check.rs         gate orchestration and envelope assembly
  check/           per-check implementations
  checks/          check identifiers and toggles
  extract.rs       tree-sitter comment-node extraction
  extract/         per-language frontends
  attribution.rs   node → channel attribution
  scope.rs         attribution-scope selection
  exemptions.rs    SPDX / generated / exclude handling
  baseline.rs      shrink-only sad-baseline.json
  config.rs        sad.toml parsing and defaults
  remediation.rs   per-check remediation templates
  envelope.rs      genesis suite envelope shaping
  model.rs         shared finding types
```

## Install

```bash
# macOS
brew install charly-vibes/charly/sad

# Windows
scoop bucket add charly https://github.com/charly-vibes/scoop-charly
scoop install sad
```

Or from source: `cargo install --path sad --locked` (or `just install` from
a clone).
